# keepass_backup

Three copies of the KeePass databases that live in a synced folder (`~/kDrive/keepass/*.kdbx`), all written
outside that folder and never overwritten. Born from a sync failure that nearly took the work database with it.

| Layer | What | Protects against | Where |
|---|---|---|---|
| 0 | KeePassXC copies the database before every save (`BackupBeforeSave`) | failed write, corruption, bad merge | `~/.local/share/keepass-backup/keepassxc/` |
| 1 | timestamped copy of every database whose content changed (KDBX signature checked), on each change (path unit) and hourly (timer) | deletion or overwrite propagated by the sync | `~/.local/share/keepass-backup/history/<db>/` |
| 2 | hourly restic snapshot on S3 object storage, writer key without delete rights, Object Lock bucket | lost machine, ransomware, mass deletion | OVH bucket, see `homelab/tofu/keepass_backup` |

A monthly timer runs `restic check`, restores the latest snapshot and compares it with the source. A failure raises a
desktop notification (`keepass-backup-notify@.service`, through `OnFailure=`), once per incident: the remote and check
services retry on failure with `RestartMode=direct` (an automatic restart skips the failed state, so `OnFailure=` does
not fire on it) and notify only when their start limit refuses the next attempt.

| Service | Retries | Notification |
|---|---|---|
| `keepass-backup-check` | 3 runs, 1 h apart (`StartLimitBurst=3` per 6 h, a run cut at 45 min) | ~3 h after the first failure |
| `keepass-backup-remote` | every 10 min, 4 to 7 runs (`StartLimitBurst=6` per 3 h, the hourly successes count too; a run cut at 15 min) | 40 to 70 min after the first failure, then about every 3 h while it keeps failing |
| `keepass-backup-local` | none (the path unit re-triggers on the next change) | on each failure |

Inside the window, a further start (the next hourly timer run, or a manual `systemctl --user start`) is refused
silently: `systemctl --user reset-failed <unit>` before starting it by hand. Windows and retry delays count awake time
only (monotonic clock): a suspend stretches them. `TimeoutStartSec=` keeps a slow or hung failing run from pushing the
next start past the window, which would retry forever without a notification. To see the alert path without breaking
anything, see « Testing the failure path » below.

Units: `keepass-backup.path` → `keepass-backup-local.service`; `keepass-backup-remote.timer` (hourly) →
`keepass-backup-remote.service` (local + restic); `keepass-backup-check.timer` (monthly) → `keepass-backup-check.service`.

## Secrets

`host_vars/<host>.sops.yaml` (sops + age) must contain:

```yaml
keepass_backup_restic:
  repository: s3:https://s3.eu-west-par.io.cloud.ovh.net/keepass-backup-sylvain
  password: <restic repository password, generated by KeePassXC, also kept on paper>
  access_key_id: <writer S3 key from `tofu output`>
  secret_access_key: <writer S3 secret>
```

Until every value is filled in (no `CHANGEME` left), only the local layers are set up and the script skips restic.
The S3 keys end up in `~/.config/keepass-backup/env` and the password in `~/.config/keepass-backup/restic-password`
(both 0600). The script loads the env file itself, so the commands below also work from a shell.

## First run

```bash
ansible-playbook playbook/setup-home.yaml --tags keepass_backup
keepass-backup init      # once, creates the restic repository
keepass-backup run       # first local copies + first snapshot
keepass-backup check     # restore test
systemctl --user list-timers keepass-backup\*
```

Restart KeePassXC once after the first run so it picks up `BackupBeforeSave`.

Retention is deliberately not run from the workstation (the writer key cannot delete snapshots). Once a year, with the
admin key from KeePassXC (procedure in `homelab/tofu/keepass_backup/README.md`):

```bash
restic forget --tag keepass --keep-within 1y --keep-monthly 24 --keep-yearly unlimited --prune
```

## Testing the failure path

A transient copy of the check service whose command always fails, with short delays (nothing of the real units changes; it raises one real desktop notification):

```bash
systemd-run --user --no-block --unit=kpb-fail-test -p Type=oneshot -p Restart=on-failure -p RestartMode=direct -p RestartSec=5s \
  -p StartLimitIntervalSec=2min -p StartLimitBurst=3 -p OnFailure=keepass-backup-notify@kpb-fail-test.service false
journalctl --user -u kpb-fail-test -f   # three runs 5 s apart, then a single notification ~15 s after the first; Ctrl-C
systemctl --user reset-failed kpb-fail-test
```

## Requirements

- `restic` installed through mise (`mise_global_plugins: {restic: latest}`), `community.sops` collection.
- KeePassXC as a flatpak (`org.keepassxc.KeePassXC`); set `keepass_backup_keepassxc_manage: false` otherwise.
